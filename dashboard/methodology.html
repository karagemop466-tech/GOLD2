⛔ NO HALLUCINATIONS — the rule everything refers back to

No value without a same-row official source link. No inference. No filled-in blanks. Unconfirmed = blank + unverified + a published flag. Hallucinated prices are the top risk in this project, so prices are transcribed only when visible on the fetched official page, with a capture date — otherwise blank. Standing recommendation after every review: keep looking for hallucinations.

Verification method

1. Source hierarchy

  1. Official pages, fetched and read (product, policy, contact, government, LBMA pages) — values transcribed; capture date recorded.
  2. Official pages, linked for manual review — cited as links only, labeled “not reviewed” where applicable.
  3. Arithmetic shown with its formula (karat ÷ 24; melt math) — checkable, not asserted.
  4. Project brief — checklist requirements from the brief, labeled as such (not official sources).

Search-result snippets are never treated as verified values; they only point at pages to fetch.

2. How each ring row is verified (line by line)

  1. Fetch the official product URL; read the full page text.
  2. Transcribe only observed fields: name, retailer, karat/metal as stated, price if visible, stock number, width, specs.
  3. Leave weight, hallmark wording, and anything else unobserved as blank + unverified; add/keep the matching flag.
  4. Record the capture date (all current rows: 2026-10-22).
  5. Run the security passes (dashboard/scripts/verify.py) after every review; fix failures before publishing.

3. Security passes (hallucination checks)

PassWhat it checks
P1-sourcesEvery ring/retailer URL is https:// on an allowlisted official domain.
P2-pricesEvery non-blank price is a positive number with a capture date; no price may exist without both.
P3-blanksEvery blank weight/hallmark/price has unverified status and a matching flag entry.
P4-crossrefRing → retailer and ring/retailer → flag references all resolve; flag IDs are unique.
P5-retailersRetailer contact/returns URLs are official-domain links with verification dates.
P8-evidenceEvery ring/retailer value traces to a verbatim quote in dashboard/evidence/*.md; source URLs echoed; price digits backed.
P6-buildGenerated pages contain every ring, retailer, and flag ID (data ↔ site in sync).
P7-linksAll internal links resolve to repo files; all external links are https://.

Run: python3 dashboard/scripts/verify.py (data passes) → python3 dashboard/scripts/build.py (render pages) → python3 dashboard/scripts/verify.py --check-build (sync + link passes) → node dashboard/scripts/calc-test.js (calculator arithmetic + negative tests). Results append to dashboard/verification-log.json.

4. How to manually re-verify (please do)

  1. Pick any row on Rings or Retailers; open its source link.
  2. Confirm the price, metal, stock number, and policy text live. Note the date.
  3. Check the Flagged for Review page for known gaps before concluding anything is “missing.”
  4. If a value here disagrees with the live official page, the live page wins — file an issue/PR with the new capture.

5. What we deliberately do NOT do

  • No spot-price snapshots (they go stale). No inferred weights, hallmarks, or “solid” claims.
  • No third-party reviews presented as fact; no retailer reputation scores.
  • No valuation of any ring; the calculator computes melt value from your inputs only.
  • No category subpages: this dashboard keeps one flat, filterable ring table — a known limitation, not a complete categorized catalog.

6. Limitations (read before relying on anything)

  • Evidence quotes prove transcription, not truth. Pass P8 checks that published values match the stored evidence files — it cannot prove the retailer told the truth. Independent testing after delivery (XRF) is still mandatory.
  • Single flat table. Five rows, one table, no category pages. Coverage is bounded, not a market inventory.
  • Point-in-time prices. Captured 2026-10-22; promotions and metal markets move them. Always re-open the source link.
  • Seller reputation unassessed. Contacts are verified; independent reviews/complaints research is yours to do (checklist item 5).
  • Calculator needs metal-only weight. Total ring weight (stones included) overstates melt value; the calculator rejects non-finite/empty input and blanks its outputs.
  • Accessibility. Dashboard text contrast was computed against WCAG AA: all running text ≥ 4.5:1; the large gold display numerals (30px bold) are 3.25:1, which meets the 3:1 large-text threshold.

Independent peer-review findings for this repository live in reviews/findings.json; this session's dispositions are recorded in COORDINATION.md. Open findings stay open until their owning session resolves them.
